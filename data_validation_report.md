# Data Validation Report — Scholarix Trust Audit

This report documents what we found when we investigated the provided dataset (50 authors, three files each: `profile.json`, `publications.json`, `broad_impact.json`) before choosing a product direction. Every number below was generated by running actual code against the actual provided files — none of it is estimated. The scripts used are simple, reproducible Python aggregations; the core prototype's audit logic (for Issue 1) lives in `backend/confidence_audit.py` in this repo.

We found five distinct data-quality issues. We built the prototype around **Issue 1** (see Product Brief for the reasoning); the other four are documented here as evidence we investigated the full dataset, and as validated directions for future work.

---

## Methodology

- **No paid tools or APIs were used.** All findings come from re-analyzing fields already present in the provided data (which itself references free/public sources: OpenAlex, Crossref, Semantic Scholar, ORCID, Google Scholar).
- **No new external API calls were made for this report.** The provided data already shows the output of prior verification attempts against these sources (e.g. `deep_verification`, `citations_all`, `orcid` fields) — our job was to audit that existing output for internal consistency, not to re-run the same lookups.
- Every statistic below is reproducible: see the inline description of each check, which can be re-run against `data/authors/*` in this repo.
- Where sources disagree, we document the disagreement rather than picking a "winner" — see Issue 2 for why that matters here specifically.

## Issue 1: Overstated AI Confidence (this prototype's focus)

**File:** `broad_impact.json` · **Records checked:** 343 across all 50 authors

Each `broad_impact.json` record carries an AI-generated `relevance_score` (0–100) and a `reasoning` sentence explaining it. These should agree in tone. We found they frequently don't: a near-perfect score paired with reasoning that hedges ("appears to be," "likely," "possibly").

| Metric | Value |
|---|---|
| Total claims audited | 343 |
| Consistent (score matches reasoning tone) | 197 (57.4%) |
| **Overstated Confidence** (high score, hedged reasoning) | **146 (42.6%)** |
| Understated Confidence (low score, definitive reasoning) | 0 (0%) |
| Average correction when flagged | −16.5 points |

**Example (most severe case found):** Philip S. Yu's Google Scholar citation record was scored 95/100, while its reasoning read: *"The snippet appears to be a citation of an academic publication..."* — hedged language attached to a near-certain score. Corrected to 80/100 by our audit logic.

**Confidence/flagging methodology:** A record is only flagged "Overstated" if its score is ≥75 **and** its reasoning contains hedge language — a low score that also hedges is treated as *honest*, not a bug (see `confidence_audit.py::audit_record` for the exact rule). This distinction matters: we're not penalizing uncertainty, we're penalizing the *mismatch* between stated and expressed uncertainty.

**Category breakdown** (where the problem concentrates):

| Category | Total | Overstated |
|---|---|---|
| Publication | 263 | 113 (43%) |
| News | 44 | 14 (32%) |
| Website | 11 | 9 (82%) |
| Conference | 13 | 7 (54%) |
| Media/Video | 11 | 3 (27%) |

Website-sourced claims are disproportionately overstated (82%) — likely because website snippets give the AI less structured signal to reason from, yet it still assigns high scores.

## Issue 2: Cross-Source Citation Disagreement

**File:** `publications.json` · **Records checked:** 5,371 across all 50 authors

Each publication carries citation counts from multiple sources (`citations_all: {openalex, crossref}`). These frequently disagree, sometimes by a wide margin.

| Metric | Value |
|---|---|
| Publications with >20-citation gap between OpenAlex and Crossref | 4,830 / 5,371 (89.9%) |
| Publications with no DOI on record | 201 (3.7%) |
| Publications with no open-access PDF found | 3,032 (56.4%) |
| Semantic Scholar could not confirm the record at all (`deep_verification.verified: false`) | 3,009 / 5,371 (56%) |

**Extreme examples found** (OpenAlex citation count minus Crossref citation count):

| Author | Publication | OpenAlex | Crossref |
|---|---|---|---|
| Bruce Hannon | "The value of the world's ecosystem services..." | 22,177 | 0 |
| Karen M. Tabb | "Global burden of 369 diseases and injuries..." | 19,617 | 0 |
| Laxmikant V. Kalé | "Scalable molecular dynamics with NAMD" | 17,444 | 0 |

**Important nuance (why we didn't build a "pick the right number" tool around this):** Crossref is fundamentally a DOI-metadata registry, not a comprehensive citation index the way OpenAlex or Semantic Scholar are — a Crossref count of 0 often means "Crossref doesn't track this," not "this paper has zero citations." Treating this gap as a simple error to correct would itself be a data-quality mistake. This is why we scoped our prototype around Issue 1 (an internal AI self-contradiction, which has no such source-coverage confound) rather than this issue (which requires understanding each source's actual coverage model to interpret correctly) — a good example of the "connect validation choices to user needs" principle: this issue needs more nuanced handling than a two-week prototype can responsibly deliver.

## Issue 3: Identity & Affiliation Ambiguity

**File:** `profile.json` · **Authors checked:** 50

| Metric | Value |
|---|---|
| Authors whose ORCID record lists multiple simultaneous "current institutions" | 18 / 50 (36%) |
| Authors whose stated `affiliation` doesn't match any ORCID-listed institution | 4 / 50 (8%) |

**Most striking example:** "I. Petrov" — profile affiliation lists **Linköping University**, but the linked ORCID record resolves to **Moscow State University** and a **Novgorod State Museum**. "I. Petrov" is a common enough name pattern (initial + common Slavic surname) that this looks like a classic author-disambiguation collision — the record may not even represent one real person.

Other affiliation/ORCID mismatches found: Kai Luo (profile: Fujian Medical University / ORCID: National University of Singapore), Qingyan Chen (profile: Hebei Medical University / ORCID: Nanyang Technological University), William P. King (profile: UIUC / ORCID: CDC/NIOSH).

**Why this matters most (per our user interviews):** Both interviewees, independently, named identity mix-ups as the single biggest trust-breaker in researcher data — more than any other issue in this report. See the Customer Interview Report. This is the strongest candidate for the next feature this product should build, even though it's out of scope for the current prototype.

## Issue 4: Silent Verification Failure

**File:** `profile.json` · **Authors checked:** 50

| Metric | Value |
|---|---|
| Authors with Google Scholar verification returning HTTP 429 (rate-limited) | 50 / 50 (100%) |
| Authors with `personal_website`, `linkedin`, and `researchgate` all null | 50 / 50 (100%) |

Every single author's `verification` block shows the same pattern: the pipeline *attempted* verification and was blocked, but the schema stores this identically to "not checked" or "nothing found." A user reading this data cannot currently distinguish "we tried and failed" from "we never looked" from "we looked and found nothing to verify." This is a data-integrity issue independent of the individual facts being right or wrong — it's about whether the data honestly represents its own confidence, which is the same underlying theme as Issue 1, just at the profile level instead of the search-result level.

## Issue 5: Duplicates & Missing Records

**File:** `publications.json` · **Records checked:** 5,371

| Metric | Value |
|---|---|
| Duplicate-titled publications within a single author's own record set | 515 |

Some authors' publication lists contain the same paper listed multiple times (likely from being pulled from more than one source and not deduplicated on ingestion). We did not build a deduplication feature around this, but flag it here as confirmed and quantified.

## Unresolved uncertainty

Some things this dataset cannot tell us, and we're not claiming otherwise:
- We have no ground truth for whether a given `relevance_score` or citation count is *factually correct* — we can only detect internal contradictions (a score vs. its own stated reasoning, or one source vs. another), not verify against reality.
- We don't know why Google Scholar verification was rate-limited for every author (infrastructure issue vs. policy vs. timing) — we report the pattern, not the cause.
- "I. Petrov" being a likely disambiguation error is inferred from circumstantial evidence (institution mismatch + common name pattern), not confirmed against an independent identity source.

Where we couldn't verify something, we've said so directly in this report rather than presenting an inferred conclusion as fact.
